The gap

Everyone has heard of AI. Most people have never watched one do real work on their own computer.

About half of U.S. adults now use AI chatbots1. But chatting is not the same as an agent that opens a folder and gets something done. Running an agent today still means a terminal, API keys, installs and config, so only a small fraction of people have ever tried one. Most never will.

How it works

From "can you take a look?" to done, in three steps.

No screen share. No remote desktop. No back and forth.

Write the job

In the dashboard, say what needs doing in plain English, pick the one folder it may work in, choose a model and decide when the code expires.

Send the code

You get a one-time code. Text it, email it, read it over the phone. They open Terminal and run:

npx gigagent K7QM-4XPA

Get the result back

The agent does the work and returns a plain-English summary for them and the answer, key findings and changes for you. Then it removes itself from their Mac.

You stay in control the whole time.

  • Watch liveEvery command and file the agent touches shows up on your dashboard as it happens.
  • Send instructionsSpotted something mid-job? Add an instruction and the agent picks it up.
  • Stop anytimeOne click revokes the session. The next model call fails and the agent halts.

Security and trust

Designed to be handed to someone who is not technical.

Some protections are built into the system. Others are rules the agent is instructed to follow, and we keep the two apart so you know which is which.

Built into the system

The AI key never reaches their Mac

The server proxies every model call. The recipient's machine only ever holds a short-lived session token, never your provider key.

Revoke a code, stop the agent

Revoke or stop a session and its next model call is refused. The agent has no model access without the server's say-so.

One-use codes

A single-use code works once. Run it again and it is rejected. You can also set codes to expire on completion or after a set time.

You watch every command live

Every command the agent runs, its output (up to 2,000 characters each) and the files it opens stream to your dashboard live, with the option to send instructions or stop.

Cleans up after itself

When the helper exits normally, it removes its temporary files from the Mac. A power loss or force-quit can leave them behind.

Rules the agent follows

These are instructions given to the agent, not technical locks. The agent's commands are not sandboxed, so treat them as strong guidance rather than a guarantee.

Works in one folder

You choose the working folder. The agent is instructed to only change things inside it. It may run read-only commands elsewhere to look up information, such as the macOS version or installed apps.

Moves instead of deleting

The agent is instructed not to delete files, empty the Trash or overwrite anything. Anything that has to go is moved aside.

Logs every move for undo

The agent is instructed to write each move to an undo log in the folder, so a clean-up can be reversed.

No sudo, installs or network

The agent is instructed never to use admin rights, install software, or download or upload anything.

FAQ

Questions people ask before they send a code.

What do they need?
A Mac with Node.js 22 or newer, plus Terminal. Node.js is a free installer from nodejs.org, and IT-managed Macs often have it already. If it is missing or too old, GigAgent explains what to do. (If Node.js is not installed at all, macOS just says command not found: npx.) They do not need an account or an API key.
Does it install anything permanently?
No permanent install. npx fetches the helper on demand, it runs once, and it removes its temporary files when it exits normally. A power loss or force-quit can leave them behind. The agent is also instructed not to install software.
What can it see?
It is instructed to work inside the one folder you pick for the job and to change nothing outside it, though it may run read-only commands elsewhere to look up information such as the macOS version or installed apps. Its commands, their output (up to 2,000 characters each) and the files it opens are streamed to you, so you see what it sees. macOS may ask the person to allow Terminal to access that folder, which is normal.
What if it goes wrong?
You can stop it from your dashboard at any time, and the person can press Ctrl+C. The agent is instructed to move files rather than delete them and to write each move to an undo log in the folder, but that is a rule it follows, not a technical lock. Revoking the code does cut off its access to the model immediately.
Which models does it use?
Models run through Vercel AI Gateway, so you can pick from Claude, GPT, DeepSeek and others per job. The model call goes through our server, never directly from the recipient's Mac.
Who sees the commands and files?
You do, as the operator: the dashboard shows each command, its output (up to 2,000 characters) and the files the agent opens. That same content is also sent to the model provider, through Vercel AI Gateway, so the model can do the job. Do not point it at a folder whose contents you would not want you or the provider to see.
Does it work on Windows?
Not yet. GigAgent is macOS only today. Windows and Linux are not supported in this version.
What does it cost?
The cost is model usage, and for a typical job like a folder clean-up or a system check that is usually cents per job. The exact amount depends on the model you choose and how long the job runs.
Does the person need an account or API key?
No. They need the code, Terminal and Node.js 22 or newer. Everything else, including the model access, is handled on your side.
